3. PROJECT ARCHITECTURE IN PLAIN ENGLISH
We are creating a virtual version of a secure small healthcare environment.

VPC = the medical office property/building boundary.
Security purpose: creates a private network under our control.

Public subnet = the front lobby.
Security purpose: where internet-facing systems could live.

Private subnet = the locked medical records room.
Security purpose: where sensitive backend systems should live.

Internet Gateway = the front door to the internet.
Security purpose: allows internet access for public resources.

Route table = traffic directions/map.
Security purpose: controls where network traffic can go.

Security group = cloud firewall.
Security purpose: allows only approved ports/sources.

KMS/encryption later = locked filing cabinet keys.
Security purpose: protects stored data.

Logging/monitoring later = security cameras and audit trail.
Security purpose: helps detect and investigate activity.

4. NETWORKING CONCEPTS TO UNDERSTAND
VPC CIDR:
10.20.0.0/16
This is the large private network range for the whole lab.

Public subnet:
10.20.1.0/24
Traditional subnet thinking:
- 10.20.1.0 = network address
- 10.20.1.255 = broadcast address

AWS reserves 5 IPs in every subnet:
- first address: network address
- second address: VPC router
- third address: AWS DNS
- fourth address: reserved by AWS
- last address: broadcast address, even though AWS does not use broadcast like a traditional LAN

Private subnet:
10.20.10.0/24
This will hold protected backend systems. It does not currently have direct internet routing.

Default route:
0.0.0.0/0 -> Internet Gateway
0.0.0.0/0 is not a host subnet. It means “all IPv4 destinations.” In a route table, this is the default route to the internet.

5. WHY PUBLIC AND PRIVATE SEGMENTATION MATTERS
Healthcare systems should not expose sensitive backend systems directly to the internet.

The secure pattern is:
Internet -> Public Web Layer -> Private Backend Layer

Not:
Internet -> Patient Database

This shows least privilege and reduced attack surface.

8. NEXT COMMANDS AND WHAT THEY MEAN
Step 1 — Move into Terraform folder:
cd /home/savib/portfolio/secure-pt-cloud/terraform
Meaning: Go where the Terraform files live.

Step 2 — Format code:
terraform fmt
Meaning: Clean up Terraform formatting. Does not create AWS resources.

Step 3 — Initialize Terraform:
terraform init
Meaning: Download the AWS provider plugin and prepare the folder. Does not create AWS resources.

Step 4 — Validate Terraform:
terraform validate
Meaning: Check whether the code is syntactically valid. Does not create AWS resources.

Step 5 — Review the plan:
terraform plan
Meaning: Preview what Terraform wants to build. This is the safety/review step.

Step 6 — Apply only after review:
terraform apply
Meaning: Actually create the AWS resources. We only run this after reviewing the plan.
